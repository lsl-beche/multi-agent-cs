# CSagent 千万用户级企业化优化方案

> 版本：v1.0 ｜ 适用：单品牌大型商城 + AI 客服（远期可扩展为多商户 SaaS）
> 现状：FastAPI 单体 + LangGraph 多 Agent 客服 + Redis/PostgreSQL/Chroma + 本地 Qwen3-1.7B + Vue 三端

---

## 0. 摘要

目标：把当前"单店演示系统"演进为**支撑千万注册用户、百万日活、大促峰值万级 QPS 的企业级电商 + 智能客服平台**。

三条主线：
1. **电商主链路真实化**：真实支付、真实物流、完整售后状态机、搜索/推荐——先补业务闭环，再谈规模。
2. **AI 客服产品化**：GPU 推理服务化、模型分层路由、Agent 编排平台化、亿级知识库、分布式记忆、人工转接中心、评测体系——这是差异化护城河。
3. **基础设施企业化**：微服务拆分、消息队列、分库分表、多可用区、弹性伸缩、全链路可观测、安全合规风控。

## 1. 现状基线

| 维度 | 现状 | 结论 |
|------|------|------|
| 架构 | FastAPI 单体，单库单服务 | 可支撑演示与数千用户，**不可支撑千万级** |

| 安全 | JWT/限流雏形，默认密钥 | 需等保/风控/密钥治理 |

## 3. 总体架构演进

### 3.1 演进路线（不推倒重来）

1. **阶段 A（单体→模块化）**：现有 FastAPI 内部按业务域拆模块、解耦数据库访问，先保证"能真实跑业务"。
2. **阶段 B（服务化）**：按域拆独立服务（用户/商品/交易/支付/物流/营销/客服/运营），引入消息队列与配置中心。
3. **阶段 C（平台化）**：多可用区部署、K8s 弹性、数据分片、AI 推理集群、开放 API。

## 4. 分层方案

### 4.1 接入与网关

- **API 网关**：Kong 或 APISIX，统一鉴权（JWT+刷新）、限流（令牌桶/漏桶按用户+IP）、路由、灰度（按用户/流量比例）、WAF。
- **边缘加速**：CDN 静态资源；WebSocket 网关独立部署（支持 20 万长连接，水平扩展）。
- **防刷**：验证码、滑动校验、设备指纹。
- **幂等**：网关层对写请求生成 request_id，服务端幂等表防重复下单/重复支付。

### 4.2 业务服务化（电商主链路）

#### 商品/搜索/推荐
- 商品服务独立，SPU/SKU/类目/属性；图片走对象存储+CDN。
- 搜索用 Elasticsearch：分词、同义词、排序（销量/价格/相关性）、聚合筛选；接入向量检索做"以图搜茶/语义搜索"。
- 推荐：初期用规则+协同过滤（离线算好放 Redis），中后期引入精排模型；冷启动用类目热榜。

#### 交易/订单
- 订单状态机已有，需补：超时未支付自动关单（延迟队列）、库存预占/回滚（分布式事务或 TCC）、订单拆单/合单、幂等下单。
- 分库分表：orders 按 user_id 哈希分 64-256 库表；订单号含分片信息。
- 读写分离 + 从库报表查询，主库只服务交易写路径。

#### 支付
- 接入真实渠道：微信支付/支付宝（服务商模式），沙箱先行。
- 支付回调验签 + 幂等；退款原路返回 + 对账（每日自动对账任务）。
- 支付风控：金额/频次/设备异常检测。

#### 物流
- 对接快递 100 / 菜鸟 / 顺丰开放平台，异步轮询或 Webhook 更新轨迹。
- 电子面单、运费模板（重量/体积/区域）、时效预测（"预计明天送达"）。

#### 营销
- 优惠券/满减/秒杀/预售/拼团；秒杀用 Redis 预扣 + 异步落库。
- 会员体系：等级/积分/成长值（现按积分推等级，需独立成长模型）。
- 价格保护、到货提醒、订阅消息（短信/App Push）。

#### 用户/评价
- 用户服务独立：实名认证、收货地址、安全（改密/换绑风控）。
- 评价：晒图（对象存储）、追评、问大家（异步问答）、商家回复；评分进入商品/店铺信誉。

### 4.3 AI 客服专项（本项目护城河）

#### 4.3.1 LLM 推理服务化

| 项 | 方案 |
|----|------|
| 推理框架 | vLLM / SGLang，PagedAttention、连续批处理 |
| 模型分层 | 意图/路由用小模型（Qwen3-1.7B/3B）；tool-calling 用 7-14B；复杂对话/总结用 32B+；云端为主、本地兜底 |
| 部署 | GPU 集群（A10/A100/H20），按模型分池，K8s HPA 弹性 |
| 量化 | AWQ/GPTQ/FP8，损失 <1% 换取 2-3 倍吞吐 |
| 并发 | 峰值 500 req/s × 平均输出 800 token ≈ 40 万 token/s，约需 8-16 张 A100（13B、TP 并行） |
| 优化 | prompt 缓存（KV Cache 复用，前缀命中率可达 60%+）、语义问答缓存（命中 60-80% 免推理）、流式首 token < 500ms |

#### 4.3.2 Agent 编排平台化
- LangGraph 工作流保留，但服务化：Agent 运行器独立部署，支持并发、超时、重试、可观测（每个节点的 token/耗时/工具调用 trace）。
- 工具注册中心 → 工具市场：插件化注册、权限分级（只读/写需确认）、限流与熔断。
- 写操作确认闭环保留并升级：提案持久化、过期、审计日志。
- 意图模型升级：从"12 类 BGE 相似度"升级为小模型微调分类器（意图+槽位+情感），支持在线评测。

#### 4.3.3 知识库工程化
- 存储：亿级向量用 Milvus（分片+GPU 索引），与 ES 关键词检索做混合召回（RRF 融合），BGE-reranker 精排。
- 管线：采集（FAQ/商品/政策/历史对话）→ 清洗 → 分块（语义切分）→ 向量化 → 质量评估（命中率/相关率）→ 灰度发布。
- 治理：知识版本化、过期检测、冲突检测、人工审核流；知识热更新事件驱动（Kafka）。
- 多语言：翻译管线 + 多语向量模型（远期）。

#### 4.3.4 记忆系统分布式化
- 会话记忆：Redis Cluster + 滚动摘要（已有，需分片与容量治理）。
- 用户偏好：从"每 6 条提取"改为事件驱动（识别到偏好信号即更新），并接入用户画像服务。
- 向量记忆：按 user_id 分片，TTL 治理（默认 90 天），隐私脱敏（不存身份证/支付信息）。
- 合规：偏好/记忆需用户授权（隐私政策 + 可删除接口"遗忘权"）。

#### 4.3.5 人工转接/联络中心
- 队列与路由：按技能组（售后/投诉/复杂问题）+ 优先级 + 平均接起时长（ASA）分配。
- 排班与预测：历史会话量预测排班。
- 会话质检：AI 全量质检（情绪、规范、解决率预测）+ 人工抽检，质检分进入客服绩效。
- 渠道：Web/App/小程序统一接入；远期对接电话（呼叫中心）与企微。

#### 4.3.6 评测与质量
- 黄金集：5000+ 条标注问答，覆盖 12+ 意图与边界场景，每次发版跑回归。
- 在线评测：A/B 对比、人工抽检、用户反馈（赞/踩/CSAT）回流训练集。
- 安全护栏：合规审查保留并升级为规则+模型双层；Prompt 注入防护；敏感信息脱敏。

#### 4.3.7 成本优化
- 语义缓存（高命中问题免推理）→ 预计减少 60-70% 推理调用。
- 模型路由：简单问题小模型，复杂问题大模型；token 预算治理（摘要/精简 prompt）。
- 批量：离线任务（摘要/偏好/质检）错峰用低价时段 GPU。
- 月度成本估算（峰值 500 req/s、13B 模型）：约 30-80 万元/月（含 GPU 与云资源），随命中率与模型路由可下降 40-60%。

### 4.4 数据层

- PostgreSQL：分库分表（用户/订单/支付），读写分离，连接池治理；核心表 JSONB 收敛为关系模型。
- Redis Cluster：缓存/会话/限流/秒杀预扣/分布式锁；冷数据自动降级。
- 消息队列：Kafka（业务事件：订单创建/支付成功/物流更新）或 RocketMQ（事务消息）；支撑最终一致与解耦。
- 数仓：ClickHouse/Doris，实时+离线，支撑运营报表与客服大屏。
- 对象存储：商品图/晒图/录音，冷热分层。

### 4.5 基础设施

- K8s 多可用区（至少 2-3 AZ），HPA + 大促定时扩容。
- CI/CD：GitOps（ArgoCD），流水线含 lint/单测/集成/冒烟/灰度。
- 弹性：网关层按 QPS 扩容，AI 层按请求队列长度扩容。
- 灾备：数据库 PITR + 跨 AZ 同步，RPO ≤ 5 分钟、RTO ≤ 30 分钟。

### 4.6 可观测性

- Metrics：Prometheus + 业务指标（下单成功率/支付成功率/客服解决率/转人工率/LLM 延迟与成本）。
- Tracing：OpenTelemetry 全链路（网关→服务→DB→LLM），识别慢路径。
- Logs：结构化日志 + 集中检索（Loki/ELK），LLM 调用全量入日志（可复盘）。
- 告警：SLO 燃烧告警，值班 on-call 轮转。

### 4.7 安全合规与风控

- 密钥管理：Vault/KMS，移除默认密钥。
- 等保三级：审计、加密传输/存储、访问控制。
- 个保法：隐私政策、最小化收集、删除权（记忆/偏好一键清除）。
- 支付合规：持牌机构合作、资金流审计。
- 风控：注册/登录风控（设备指纹、行为序列）、反刷单（订单频次/收货地址聚类）、反薅羊毛（券领取风控）。

### 4.8 前端与多渠道

- Web：SSR/预渲染 + 代码分割（Element Plus 按需引入已完成）+ 图片 WebP/懒加载。
- 多端：H5/App（uni-app 或 Flutter）/小程序共用业务 API；客服悬浮窗抽为跨端组件。
- 性能：CDN、HTTP/3、骨架屏、PWA 离线。
