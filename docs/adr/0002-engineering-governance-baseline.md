# ADR-0002：P0 工程治理基线

状态：accepted  
日期：2026-08-30  
决策人：项目负责人  
评审人：后端、前端、DevSecOps

## 背景

项目当前没有 Git 仓库、没有可执行的远程分支保护，CI 文件存在但质量门禁不完整，环境变量和设计决策没有统一治理。

## 决策

建立以下工程基线：

1. `main` 为受保护默认分支；
2. 功能、修复、安全和发布使用独立分支；
3. 所有变更通过 Pull Request；
4. CI 必须运行 lint、type check、pytest、前端构建；
5. 所有影响架构、安全、数据、部署的变更增加 ADR；
6. 环境变量统一通过 `.env.example` 和 `docs/env-spec.md` 管理；
7. 敏感文件禁止进入 Git；
8. 发布必须保留上一版本并支持回滚。

## 备选方案

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 直接使用全局/mixed 配置 | 简单 | 不可复现、不安全 | 不采用 |
| 统一工程治理基线 | 可审计、可回滚、可协作 | 初期成本较高 | 采用 |

## 影响

- 新增文档：CONTRIBUTING、branch protection、env-spec、ADR；
- CI 门禁在 P0 先以现有能力为准，后续逐步达到 70% 覆盖率和安全扫描；
- 所有新增代码必须符合分支、PR、ADR 和提交规范。

## 验证

- Git 初始提交完成；
- `git check-ignore` 排除 `.env`、`.venv`、`models/`；
- CI 工作流可被远程仓库识别；
- 文档和模板可在后续 PR 中复用。
